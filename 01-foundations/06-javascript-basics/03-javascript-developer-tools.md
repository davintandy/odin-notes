# JavaScript Developer Tools

## What Are JavaScript Developer Tools?

**Developer Tools (DevTools)** are built-in browser tools that help developers inspect, test, debug, and improve web applications.

Chrome DevTools provides several tools for working with JavaScript, HTML, and CSS.

### Why Use DevTools?

- Run JavaScript code without modifying project files.
- Inspect variable values and program output.
- Identify syntax errors and runtime errors.
- Pause JavaScript execution to investigate problems.
- Trace code execution step by step.
- Inspect and temporarily modify the DOM.
- Test changes without repeatedly editing and reloading source files.

### Important DevTools Panels

| **Panel** | **Purpose** |
| --- | --- |
| **Elements** | Inspect and modify the DOM and CSS |
| **Console** | Execute JavaScript and view messages, warnings, and errors |
| **Sources** | Inspect source files, set breakpoints, and debug JavaScript |
| **Network** | Inspect network requests and loaded resources |
| **Performance** | Analyze page performance and execution |
| **Application** | Inspect browser storage, cookies, and application resources |

## Opening Chrome DevTools

There are several ways to open Chrome DevTools.

### Method 1: Right-Click

1. Open a webpage in Chrome.
2. Right-click anywhere on the page.
3. Select **Inspect**.

DevTools opens with the selected HTML element highlighted in the Elements panel.

### Method 2: Keyboard Shortcuts

| **Action** | **Shortcut** |
| --- | --- |
| Open DevTools | `F12` or `Ctrl + Shift + I` |
| Open element inspector | `Ctrl + Shift + C` |
| Open Console | `Ctrl + Shift + J` |

You can also press `Esc` while DevTools is open to show or hide the Console drawer in many DevTools layouts.

### Method 3: Chrome Menu

1. Open Chrome’s three-dot menu.
2. Select **More tools** → **Developer tools**.

## The Console

The **Console** is one of the most useful tools for JavaScript development.

It has two main purposes:

1. Display messages generated by JavaScript.
2. Execute JavaScript directly in the browser.

### Using `console.log()`

The `console.log()` method displays information in the Console.

```jsx
console.log("Hello, World!");

let age = 25;

console.log(age);
console.log(10 + 20);
```

Output:

```
Hello, World!
25
30
```

This is useful for checking variable values and verifying whether particular sections of code are executing.

### Multiple Values

You can pass multiple arguments to `console.log()`.

```jsx
const firstName = "John";
const age = 25;

console.log("Name:", firstName, "Age:", age);
```

Output:

```
Name: John Age: 25
```

### Other Useful Console Methods

| **Method** | **Purpose** | **Example** |
| --- | --- | --- |
| `console.log()` | Displays a general message | `console.log("Hello")` |
| `console.info()` | Displays informational messages | `console.info("Loading")` |
| `console.warn()` | Displays a warning | `console.warn("Check this value")` |
| `console.error()` | Displays an error message | `console.error("Something went wrong")` |
| `console.table()` | Displays arrays or objects in a table | `console.table(users)` |
| `console.assert()` | Displays a message when a condition is false | `console.assert(age > 0, "Invalid age")` |
| `console.clear()` | Clears the Console | `console.clear()` |

Example using `console.table()`:

```jsx
const users = [
	{ name: "John", age: 25 },
	{ name: "Jane", age: 22 },
	{ name: "David", age: 28 }
];

console.table(users);
```

This displays the array of objects in a table, making structured data easier to inspect.

### Running JavaScript Directly in the Console

The Console also functions as a **REPL (Read-Eval-Print Loop)**.

This means you can type JavaScript expressions, execute them, and immediately see their results.

```
1 + 2
```

Output:

```
3
```

You can also declare variables and call functions:

```jsx
const price = 100;
const quantity = 3;

price * quantity
```

Output:

```
300
```

### Interacting with the Current Webpage

The Console can access the webpage’s JavaScript environment and DOM.

For example:

```jsx
document.title
```

Displays the current page title.

You can also temporarily change it:

```jsx
document.title = "My New Title";
```

The browser tab title changes immediately.

**Important**: Code entered directly into the Console is generally temporary. It does not automatically modify your original JavaScript, HTML, or CSS files.

## Debugging JavaScript

**Debugging** is the process of identifying, investigating, and fixing errors in a program.

Instead of guessing why something is not working, debugging tools allow you to examine the program while it executes.

### Types of Errors

| **Error type** | **Description** | **Example** |
| --- | --- | --- |
| Syntax error | Code violates JavaScript syntax rules | Missing closing bracket |
| Runtime error | An error occurs while the code is executing | Calling a method on `null` |
| Logical error | Code runs but produces an incorrect result | Using `+` instead of `*` |

Example of a syntax error:

```jsx
console.log("Hello World"
```

The closing parenthesis is missing.

Example of a runtime error:

```jsx
const user = null;

console.log(user.name);
```

JavaScript throws a `TypeError` because `null` does not have a `name` property.

Example of a logical error:

```jsx
const width = 10;
const height = 5;

const area = width + height;

console.log(area); // 15
```

The code runs successfully, but the calculation is incorrect because the area should be calculated using multiplication.

### The Sources Panel

The **Sources panel** provides access to the files loaded by the webpage and includes JavaScript debugging tools.

It commonly contains three main areas:

1. **File Navigator**: Displays loaded HTML, JavaScript, CSS, and other resources.
2. **Code Editor**: Displays the selected source file.
3. **Debugger**: Provides controls and information for investigating JavaScript execution.

You can select a JavaScript file to inspect its code and set breakpoints on specific lines.

## Breakpoints

A **breakpoint** is a marker that tells the debugger to pause JavaScript execution at a particular point.

Instead of allowing an entire script to execute immediately, you can stop it and examine what is happening.

### Setting a Breakpoint

1. Open Chrome DevTools.
2. Navigate to the **Sources** panel.
3. Open the JavaScript file you want to inspect.
4. Find the line where you want execution to pause.
5. Click the line number.

When JavaScript reaches that line, execution pauses before the statement runs.

### Example

```jsx
function calculateTotal(price, quantity) {
	const total = price * quantity;
	
	console.log(total);
	
	return total;
}

calculateTotal(100, 3);
```

You can place a breakpoint on:

```jsx
const total = price * quantity;
```

When execution pauses, you can inspect:

- The current values of `price` and `quantity`.
- The current function being executed.
- The values of local variables.
- The upcoming statement before it executes.

### Managing Breakpoints

The Breakpoints section in the debugger allows you to:

- Enable or disable breakpoints.
- Remove individual breakpoints.
- Navigate directly to a breakpoint.
- Manage multiple breakpoints across different files.

Breakpoints are useful when you know approximately where a problem occurs and want to inspect the program at that exact location.

## Types of Breakpoints

Chrome DevTools supports several breakpoint types.

| **Breakpoint type** | **Purpose** |
| --- | --- |
| Line-of-code | Pauses execution at a specific line |
| Conditional | Pauses only when a specified condition is true |
| Logpoint | Displays a message in the Console without pausing execution |
| DOM change | Pauses when a particular DOM node is modified or removed |
| Event listener | Pauses when a particular event, such as a click, is triggered |
| Exception | Pauses when JavaScript throws an exception |
| XHR / Fetch | Pauses when a network request matches a specified URL pattern |
| Function | Pauses when a network request matches a specified URL pattern |

### Conditional Breakpoints

A conditional breakpoint pauses execution only when a specified expression evaluates to `true`.

For example:

```jsx
for (let i = 0; i < 10; i++) {
	console.log(i);
}
```

Suppose you only want to pause when `i === 5`.

1. Right-click the line number.
2. Select **Add conditional breakpoint**.
3. Enter:

```jsx
i === 5
```

The debugger pauses only when the condition becomes `true`.

This is especially useful when debugging loops or functions that execute many times.

### Logpoints

A logpoint displays a message in the Console without stopping the program.

This allows you to inspect values without adding `console.log()` statements to your source code.

For example, you could create a logpoint with:

```jsx
"Current value:", i
```

Whenever execution reaches that line, DevTools displays the message and the current value of `i`.

## The `debugger` Statement

JavaScript provides a special statement called `debugger` that pauses execution when developer tools are open.

```jsx
function calculateTotal(price, quantity) {
	const total = price * quantity;
	
	debugger;
	
	return total;
}
```

When the function executes:

1. JavaScript calculates `total`.
2. Execution pauses at `debugger`.
3. You can inspect variables and expressions.
4. You can continue or step through the remaining code.

The statement is ignored when no active debugger is available.

### When to Use It

- Investigating a suspicious section of code.
- Checking the values passed into a function.
- Understanding how a variable changes.
- Finding where an unexpected result first appears.

Remove unnecessary `debugger` statements before committing production code.

## Inspecting Variables While Paused

When JavaScript execution is paused, the debugger provides several useful sections for examining the current program state.

### Watch

The **Watch** section lets you monitor specific expressions or variables.

For example:

```jsx
let price = 100;
let quantity = 3;

let total = price * quantity
```

You can add the following expressions to Watch:

```jsx
price
quantity
total
price + quantity
```

DevTools displays their current values and updates them as execution progresses.

### Scope

The **Scope** section displays variables available at the current execution point.

Common categories include:

| **Scope** | **Meaning** |
| --- | --- |
| Local | Variable belonging to the current function |
| Closure | Variables accessible from surrounding lexical scopes |
| Global | Variables available in the global scope |

The exact sections displayed depend on the current execution context.

### Call Stack

The **Call Stack** shows the sequence of function calls that led to the current point in execution.

Consider:

```jsx
function say(message) {
	console.log(message);
}

function greet(name) {
	const message = `Hello, ${name}!`;
	
	say(message);
}

greet("John");
```

The call sequence is:

```
greet("John")
    |
    v
say("Hello, John!")
    |
    v
console.log(message)
```

The Call Stack helps you understand which functions called one another and where the current execution is located.

You can select a stack entry to inspect the corresponding function and its available variables.

## Stepping Through JavaScript Execution

When execution is paused, you can control how JavaScript continues.

The debugger provides several execution controls.

| **Action** | **Shortcut** | **Purpose** |
| --- | --- | --- |
| Resume | `F8` | Continues execution until another breakpoint or the end |
| Step | `F9` | Executes the next statement |
| Step over | `F10` | Executes the next statement without entering a called function |
| Step into | `F11` | Enters a function call to inspect its execution |
| Step out | `Shift + F11` | Continues until the current function returns |

Keyboard shortcuts can vary depending on the operating system and DevTools configuration.

### Step

Execute the next statement and pauses again.

Useful when you want to follow the execution of a program one line at a time.

### Step Over

Executes the next statement without entering the internal code of a function call.

Useful when you know a function works correctly and do not need to inspect its implementation.

### Step Into

Enters a function call and pauses inside that function.

Useful when you suspect the problem is happening within another function.

### Step Out

Finishes executing the current function and pauses when it returns to its caller.

Useful when you have entered a function but no longer need to inspect its internal execution.

### Resume

Continues normal execution until another breakpoint is reached.

### Example

```jsx
function multiply(a, b) {
	return a * b;
}

function calculate() {
	const result = multiply(5, 3);
	console.log(result);
}

calculate();
```

Place a breakpoint on:

```jsx
const result = multiply(5, 3);
```

Then experiment:

- **Step Into**: Enter the `multiply()` function.
- **Step Over**: Execute the function without inspecting its internal code.
- **Step Out**: Finish the current function and return to its caller.
- **Resume**: Continue execution until the next breakpoint or completion.

## Pause on Exceptions

DevTools can automatically pause JavaScript execution when an exception occurs.

This is useful when you do not know exactly where an error originates.

In the Sources panel, find the pause-on-exceptions control and enable it.

Chrome commonly provides two modes:

- **Pause on uncaught exceptions**: Pauses when an exception is not handled by the program.
- **Pause on caught exceptions**: Also pauses when an exception is caught by a `try...catch` block.

Example:

```jsx
const user = null;

try {
	console.log(user.name);
} catch (error) {
	console.log("An error occurred:", error);
}
```

When pause on caught exceptions is enabled, the debugger can pause at statement that throws the error, even though the `catch` block handles it.

This helps identify the original cause rather than only examining the error-handling code.

## Inspecting the DOM Through DevTools

The **DOM (Document Object Model)** is the browser’s structured representation of an HTML document.

The Elements panel allows you to inspect and temporarily modify the DOM while a webpage is running.

### Selecting Elements

1. Open the Elements panel.
2. Use the element selection tool to click an element on the webpage.
3. Locate the corresponding node in the DOM tree.

You can also right-click an element on the webpage and choose **Inspect**.

### Searching the DOM

Press `Ctrl + F`

You can search using:

- Text content.
- CSS selectors.
- XPath expressions.

For example, searching for:

```jsx
.card
```

Locates elements with the `card` class.

### Modifying DOM Elements

You can temporarily change the webpage without editing its original HTML file.

For example, to change text:

```html
<h1>Hello World!</h1>
```

Double-click the text in the DOM tree and replace it with:

```
Welcome to JavaScript!
```

You can also:

- Edit element attributes.
- Change an element's tag name.
- Edit larger sections using **Edit as HTML**
- Duplicate elements.
- Reorder DOM nodes.
- Hide elements.
- Force pseudo-class states such as `:hover` and `:focus`.

### Important: DOM vs. Original HTML

The DOM displayed in DevTools represents the current live document.

JavaScript may modify the DOM after the original HTML has loaded.

Therefore, the DOM tree may not exactly match the original HTML source file.

Changes made directly in DevTools are temporary by default. Reloading the webpage generally discards them unless you have configured a persistence workflow.

## DOM Change Breakpoints

A **DOM change breakpoint** pauses JavaScript execution when a selected DOM element changes.

This is useful when an element is unexpectedly modified, removed, or updated by JavaScript.

### Types of DOM Change Breakpoints

| **Type** | **Purpose** |
| --- | --- |
| Subtree modifications | Pauses when children inside an element are added, removed, or changed |
| Attribute modifications | Pauses when an element’s attribute change |
| Node removal | Pauses when the selected element is removed |

### Setting a DOM Breakpoint

1. Open the Elements panel.
2. Select the element you want to monitor.
3. Right-click the element.
4. Select **Break on**.
5. Choose the appropriate breakpoint type.

For example, use **Subtree modifications** when you want to identify which JavaScript code is adding or removing content inside a particular element.

When the DOM changes, DevTools pauses execution at the code responsible for the modification.

## A Practical JavaScript Debugging Workflow

1. **Check the Console**. Look for syntax errors, runtime errors, and unexpected output.
2. **Inspect variable values**. Use `console.log()` to verify the values being processed.
3. **Locate the relevant source file**. Open it in the Sources panel.
4. **Set a breakpoint**. Pause execution near the suspicious code.
5. **Inspect the current state**. Use Watch, Scope, and Call Stack to understand what is happening.
6. **Step through execution**. Use Step Into, Step Over, and Resume to follow the program.
7. **Inspect the DOM if necessary**. Check whether JavaScript is changing webpage elements unexpectedly.
8. **Fix the original source code**. Make changes in your editor rather than relying on temporary DevTools modifications.
9. **Reload and test again**. Confirm that the problem has been resolved.

### Debugging Best Practices

- Start with the error message and the line number provided by the browser.
- Read the entire error message instead of focusing only on the first line.
- Use breakpoints when `console.log()` is insufficient.
- Check variable values before and after important operations.
- Avoid adding too many unrelated `console.log()` statements.
- Remove unnecessary debugging statements before committing your code.
